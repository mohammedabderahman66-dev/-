# مقترح 04 — تقرير فحص أمني (لا تنفيذ بعد، للمناقشة والسد لاحقاً)

**الحالة:** 🔍 تقرير اكتشاف فقط — بانتظار نقاش وخطة سد
**التاريخ والوقت:** 2026-11-17 09:00 UTC
**الكاتب:** claude (جلسة المحادثة الرئيسية مع محمد)
**السياق:** طلب محمد فحصاً أمنياً شاملاً للمستودع الحالي (الحالة بعد إغلاق مقترح 01). المستودع **عام** حالياً (تحقّقت عبر API)، ما يرفع خطورة بعض النقاط أدناه لأن أي شخص يصل لكود المصدر وللـ APK المنشور.

لم أنفّذ أي إصلاح — فقط توثيق، حسب قواعد التعاون.

---

## 🔴 حرج

### 1. ثغرة حرجة في حزمة `tar` (عبر `@capacitor/cli`)
`npm audit` يُظهر `tar <=7.5.20` بتصنيف **critical**: كتابة/استبدال ملفات عشوائية عبر hardlink/symlink path traversal، وDoS عبر مدخلات غير محدودة (11 ثغرة موثّقة في GHSA). الحزمة تأتي عبر `@capacitor/cli` → `rimraf` → `tar`.
- **الأثر:** يؤثر على بيئة البناء (أي جهاز/CI يُشغّل `npm install`/`npx cap ...`) وليس على التطبيق المُثبَّت نفسه مباشرة — لكنه خطر حقيقي على كل من يبني هذا المشروع، بما فيه GitHub Actions.
- **الإصلاح المتاح:** `npm audit fix --force` يرفع `@capacitor/cli` إلى `8.6.2` — **تغيير جذري (breaking change)**، يحتاج اختباراً كاملاً لسلسلة `cap sync android` و`gradlew assembleDebug` بعد الترقية قبل الدمج.

## 🟠 عالٍ

### 2. توزيع APK تجريبي (debug) على Release عام
الـ workflow يبني `assembleDebug` فقط ويرفعه كـ GitHub Release عام. الـ debug build type في أندرويد:
- مُوقَّع بمفتاح debug الافتراضي المشترك بين كل تثبيتات Android SDK في العالم (ليس مفتاحاً فريداً لهذا المشروع) — أي أحد يقدر يعيد توقيع نسخة معدَّلة (ربما خبيثة) بنفس التوقيع.
- عادة `debuggable=true` ضمنياً لنوع البناء debug، ما يسمح لأي شخص يملك وصولاً فعلياً للجهاز (أو عبر ADB) بإرفاق Debugger وقراءة/تعديل الذاكرة أثناء التشغيل، بما فيها أي بيانات حساسة تُعالَج وقت التشغيل.
- **التوصية:** عدم نشر أي debug build للعامة. إما (أ) الانتقال لـ `assembleRelease` بمفتاح توقيع مخصص (مخزَّن كـ GitHub Secret)، أو (ب) إبقاء التوزيع الحالي لاختبار داخلي صريح فقط (مستودع خاص مؤقتاً، أو Release بعلامة `prerelease`/تحذير واضح أنه "للتطوير فقط، غير آمن للتوزيع").

### 3. استخدام third-party GitHub Action بصلاحية كتابة ومثبَّت بوسم متغيّر
`softprops/action-gh-release@v2` مثبَّت بوسم (`v2`) لا بـ commit SHA ثابت، والـ workflow يملك `permissions: contents: write`. إذا تم اختراق هذا الوسم لاحقاً من المصدر (هجوم سلسلة توريد معروف الحدوث فعلياً لأكشنات مشابهة)، فسيحصل كود غريب على صلاحية كتابة كاملة على المستودع تلقائياً عند أي push.
- **الإصلاح المقترح:** تثبيت الأكشن بـ commit SHA كامل بدل الوسم (نفس المبدأ يُستحسن لـ `actions/checkout@v4` و`setup-node@v4` و`setup-java@v4` كدفاع إضافي، رغم أنها رسمية وأقل خطورة).

## 🟡 متوسط

### 4. `android:allowBackup="true"` بلا أي استثناء للبيانات الحساسة
`AndroidManifest.xml` الحالي لا يحدد `android:allowBackup="false"` ولا `dataExtractionRules`/`fullBackupContent`. هذا غير خطير الآن (لا بيانات حساسة مخزَّنة بعد)، **لكنه سيصبح خطيراً بمجرد تنفيذ مقترح 02** (Device Flow): حتى لو خُزِّن الـ token في Android Keystore بأمان (غير قابل للنسخ الاحتياطي أصلاً)، أي بيانات أخرى يخزّنها WebView (localStorage، IndexedDB، SharedPreferences) ستُنسخ احتياطياً افتراضياً (عبر adb backup أو النسخ الاحتياطي السحابي لأندرويد) ما لم تُستثنَ صراحة.
- **التوصية:** يُحسم هذا **قبل** إغلاق مقترح 02، بإضافة `dataExtractionRules.xml` يستثني أي مسار يخزّن فيه WebView بيانات الجلسة، أو ببساطة `allowBackup="false"` إن لم تكن ميزة النسخ الاحتياطي مطلوبة للمستخدم.

## 🟢 منخفض / ملاحظات للمستقبل

### 5. `minifyEnabled false` في بناء الـ release
لا تصغير ولا تعتيم للكود في `build.gradle` (`buildTypes.release`). ليس ثغرة بذاته، لكنه يسهّل الهندسة العكسية لأي كود مستقبلي. يعزّز أهمية الالتزام الصارم بقرار "لا مفاتيح API مضمَّنة في التطبيق" المتفق عليه مسبقاً — لأنه بدون تصغير، أي اختراق لهذا القرار لاحقاً (حتى بالخطأ) سيكون مكشوفاً بسهولة أكبر لأي شخص يفحص الـ APK.

### 6. اسم الإصدار في الـ workflow لم يُحدَّث بعد
`name: "AppForge Test Build #${{ github.run_number }}"` ما زال يحمل الاسم القديم رغم إتمام مقترح 01 (Warsha). ليس أمنياً، لكنه تناقض اكتُشف أثناء الفحص ويستحق تصحيحاً سريعاً ضمن أي commit قادم على نفس الملف.

### 7. لا تهيئة صريحة لأمان الشبكة بعد (للمراقبة فقط الآن)
لا يوجد `networkSecurityConfig` ولا إعداد `server` في `capacitor.config.json` حالياً — لا خطر فعلي اليوم لعدم وجود اتصالات شبكة مخصصة بعد. **يجب التعامل معه عند تنفيذ مقترح 02**: فرض HTTPS فقط (`usesCleartextTraffic=false` صراحة وليس بالاعتماد على الافتراضي فقط)، خصوصاً أن Device Flow يمرّر رموز وصول حقيقية عبر الشبكة.

- قوالب `templates/*` الخاصة بمقترح 03 للسبب نفسه.
